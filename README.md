# Phase 3.5 历史与生活事件融合

保留 Phase 3.4 的全部原始文件与数据库，只增加 `data/simulation/history_life_events_v1.json`、`js/simulation/historyLifeEngine.js`，并修改三个接入文件：`worldStateEngine.js`、`simulationApp.js`、`simulation.html`。

## 设计
- 世界时间到达预设时刻，触发一次性事件。只有玩家在场才显示事件并提供选择；不在场则标记错过，防止无处不在的剧情。
- 选择暂停世界时间，结束后写入玩家长期记忆和事件存档。
- 事件记录保存于原有 `hogwarts_world_simulation_v1` 存档键，兼容旧版 v1-v3。
- 万圣节原著事件目前仅预约并提供非剧透的氛围铺垫；完整主线将在下一阶段制作。
- 1×/2×/4×/8× 世界时间及 NPC 社交保持原有机制。

## 测试
用 Live Server 打开 `simulation.html`，9月2日08:00在礼堂会遇到早餐选择；15:45在走廊可遇到新生；9月4日16:30在图书馆可能遇到传闻。每个事件只能发生一次。若事件时不在场，则不会强制传送玩家。

## 内容扩展规则
新增条目必须有唯一 `id`、ISO本地游戏时间 `at`、`location`、原创 `text`、可选 `choices`。重要正史人物预约仅作元数据，不改变其原著关键经历。后续可将现有 `historical_events.json` 的经过校验的事件映射为统一日程，但不要直接复制所有条目或将传闻当成正史。

## 现阶段限制
- 未实现完整主线事件演出、事件多地点传播、NPC事件冲突的强制预约或课程表精确重排。
- 浏览器真实端到端及手机测试仍需进行。


## Phase 3.6 人物记忆驱动决策

- NPC选择社交对象时，计算历史互动记忆的衰减偏好；同地点、冷却和时间约束仍有效。
- NPC选择聊天、自习或休息时，记忆会给活动效用增加有上限的权重。
- NPC主动邀请玩家时，考虑与玩家的长期记忆（含交谈和邀请结果）。
- 记忆影响随游戏天数指数衰减，21天半衰期，可在 npc_network_memory_rules.json 中调整。
- 旧存档版本1至4继续可读；新版保存版本5。所有旧JSON文件保留，仅扩展现有规则JSON。
- 这是第一版基于记忆的决策偏好，不包括谣言传播、复杂群体冲突或正史角色的严格预约锁。


## Phase 4.1 九月主线与托管模式
- 新增 `data/simulation/mainline_september_v1.json`：7个九月原创主线场景，每个3个选项，地点不匹配则按原规则错过。
- `simulation.html` 新增手动、自动、托管模式；托管模式对事件和NPC邀请自动决策，随机状态随存档保存。
- 托管模式不会自动移动玩家，因而可能错过不同地点的主线；后续可增加日程导航AI。
- 模式选择单独存于localStorage；不修改已有JSON。
